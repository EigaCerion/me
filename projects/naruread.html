NaruReader — Self-Hosted Comic Library

A personal comic reader that runs on my own machine: local library, no ads, no third-party accounts — readable from my phone over home Wi-Fi.

Full-stack Self-hosted Security-minded
Problem

I wanted my own comic library — not someone else's platform.

Reading apps and sites come with ads, accounts I don't need, and no guarantee my collection stays available. I wanted something that keeps everything on my own disk, works from my phone over my home network, and doesn't phone home to anyone.

Approach

A real client-server app: Express + SQLite on the back end, React on the front.

NaruReader is a monorepo with an Express/SQLite/Sharp API and a React 18 + Vite + Tailwind + RTK Query front end. A few pieces I'm most proud of:

  • An automatic WebP compression pipeline for imported pages — benchmarked, not guessed at, and tuned after measuring quality-vs-size tradeoffs directly rather than assuming higher settings were worth the extra time.
  • A SQLite-backed download queue with importer and "supervisor" worker bots: the supervisor re-checks completed chapters for corrupt or missing pages and re-queues only what's actually broken.
  • Full-text search via SQLite FTS5, with prefix matching and a fallback for older data.
  • Role-based accounts (reader, author, editor, publisher, super admin) — but reading requires no login at all; accounts only unlock rating, commenting, and library management.
  • LAN access designed in from the start: the API serves the built front end directly, so a phone on the same Wi-Fi only needs one port, with a PWA manifest for an "app-like" home-screen icon.
Security

Treated as a real app, not a weekend hack.

Since it's reachable on a home network, I built in the basics properly rather than skipping them:

  • A domain allowlist for anything the server downloads from, with localhost and private IPs always rejected — closes off SSRF through the download feature.
  • All file paths go through a safeJoin() helper that guarantees the resolved path can't escape the data directory, preventing directory traversal.
  • Every database query is parameterized — no string-built SQL, including in search and pagination.
  • Passwords hashed with scrypt, sessions use random 256-bit tokens in HttpOnly cookies, and disabling an account immediately revokes its sessions.
  • Uploads are restricted to image MIME types with size/page limits and are held in memory and compressed rather than ever written to disk raw.
Outcome

Measured, not assumed.

Because the compression pipeline has a benchmark script, the numbers here are actual measurements, not estimates:

  • ~73% file-size reduction on a real test page set (1600×2400 source images), at WebP quality 75 — the documented target was 70–80%, and the benchmark confirmed it lands there.
  • Already-optimized images are passed through untouched (zero re-encoding, zero quality loss) instead of being re-compressed for no reason.
  • Downloads survive interrupted connections: pages are written to a temp file and atomically renamed, so a crash mid-download never leaves a corrupt page mistaken for a valid one — only the genuinely missing pages are re-fetched on resume.
